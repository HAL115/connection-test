# Overview

観測と記録を売りにするサイトである。デザインの基準はファクット（https://facutto.jp/）とし、可能な限り同様の見た目に近づける（2026-11-24、Fujii指示）。寄せるのはレイアウト・配色・階層・部品の見せ方で、相手のロゴマーク等の固有の商標・画像・文言は複製しない。順位の見せ方は当サイトの実データ（透明性スコア等）で組み替える。抽出と差分の正本は files/ファクット_デザイン抽出と差分_20261124.md。

# Colors

- primary（明るいティール）: 見出し、リンク、タブ、バッジ。地は淡ミント（bg）に白カードを影で浮かせる。
- cta（アンバー）: 行動のボタンは #F59E0B→#D97706 のグラデーションで作る。ヘッダーのCTAはピル型。本文のリンクや装飾には使わない。ページ内で最も目立つ色は常にCTAであること。
- gold: 数字の強調と順位の装飾だけに使う。本文では使わない。
- 線は line を最小限に使い、カードの分離は影を主体にする。文字と背景のコントラストは4.5:1以上を保つ。

# Typography

- 書体は Noto Sans JP。ウェイトは400／500／700／900のみ。
- 日本語の本文には letter-spacing 0.02em を付ける。見出しは 0.02〜0.03em。英数字のラベル（eyebrow）は 0.18em で大きく開ける。
- 数字は tabular-nums で桁をそろえる。金額と件数の数字は必ず出典か確認日と組で置く。
- 行間は本文1.85、見出しはサイズに応じて1.3〜1.6。本文の1行は最大で42文字程度に収める（読み幅 1024px の中で本文幅を絞る箇所は 720px）。

# Layout

- 読み幅は最大1024px、左右パディング20px。
- セクションの間隔は72px。セクション見出しには番号つきの eyebrow（例: 03 — OBSERVATION）を置く。
- カードは角丸14px、線1px（line）、影は 0 1px 2px rgba(20,40,38,.05) と 0 8px 24px rgba(20,40,38,.06) の二重。ホバーで影を強くし、2pxだけ浮かせる。

# Components

- ボタン: 高さは主CTA 60px、通常 56px、小 48px。タップ領域は44px以上（デジタル庁デザインシステムの規則）。ラベルは letter-spacing 0.04em、ウェイト700。主CTAには影（0 6px 20px rgba(194,65,12,.35)）を付ける。
- 選択肢カード（チェックの質問）: 最小高さ64px、線2px、選択時はCTA色の線と淡い地。ホバーで primary の線。
- バッジ: 透明性スコアは primary の地に白文字。注意のバッジは地を #8A8578 にする。
- 表: 見出し行は chip-bg。数字の列は右寄せにせず、桁ぞろえ（tabular-nums）で読ませる。行のホバーで地を薄く変える。列が4つ以上の表は最小幅640pxを付け、狭い画面では横スクロールにする（潰して縦に割らない）。
- 一覧の表示: スマホでは表にせずカードにする。件数が多い一覧は最初は15件まで表示し、「残り n 件を表示する」で15件ずつ足す。全件を一気に並べてページを無限に長くしない。
- ヘッダー: 高さは固定しない。スマホではサイト名15px・副題は出さない。ヘッダーのCTAは改行させない（nowrap）。下部固定CTAはセーフエリア分の余白を持ち、ボタン文言をはみ出させない。
- 手法ガイド（全24手法）は縦に羅列せず、横スクロールのカード列（スナップ付き、幅292〜330px）で限られた高さに収める。
- リード獲得: 状態チェックの結果は連絡先なしで最後まで表示する。その末尾に「現状シート」（結果と現状を1枚にまとめた、担当者へ渡せるシート）の作成フォームを置き、連絡先（会社名・担当者名・メール・任意で電話）の入力と引き換えにシートを渡す。連絡先を取得するのはこの作成時だけ。
- コピーは短く保つ。1ブロックで伝えることは1つに絞り、説明の重複を置かない。
- 数字の組み方: 手数料と金額は、下限と上限が同じ値なら1つだけ書く。下限が無い項目は上限だけを書く（「―〜」のような空の範囲を作らない）。
- PR表示: 地 #FFF3D6、線 #D9A400 のチップ。広告を含むページの冒頭に必ず置く。

# Motion

- セクションは表示領域に入ったときに、下から18px、0.7秒（cubic-bezier(.22,.61,.36,1)）で現れる。
- ヒーローの数字はカウントアップで見せる（1.2秒）。
- チェックのステップ遷移はフェード＋8pxのスライド。
- prefers-reduced-motion の場合は全ての動きを止める。

# Do's and Don'ts

- Do: 数字には出典と日付を付ける。CTAは「何が起きるか」が分かる文言にする（例: 状態チェックをはじめる／候補 n 件を比べる）。
- Do: ヒーローの1画面に、見出し、証拠、主CTAの3つを収める。
- Don't: 根拠のない金額の目安、最上級の表現、結果の約束を書かない。
- Don't: CTA色を装飾に使わない。金色を本文で使わない。
- Don't: 実表示で読めない小さい文字を置かない（最小は12px、注記でも13pxを原則とする）。

## ヘッダーと検証の規則（2026-11-20）
- ヘッダーは「ロゴ／状態チェック／メニューボタン」の1行だけ。ナビの帯をヘッダーにぶら下げない。全ページ共通のメニューは、ボタンで開く全画面パネル（大きなタップ領域、説明つき）に入れる。全記事への導線はフッターのサイトマップ（基礎知識／状態別／手法／比較の全リンク）が担う。
- レイアウト変更は、公開前にモバイル幅（320／360／390／430px）の実寸レンダリングを撮影して目で見てから出す。コードの読みで「直った」と判断しない。下部の固定バーは box-sizing と min-width:0、文字のはみ出しは省略表示で構造的に防ぐ。
- 下部の固定バーは、横並びの組み立て（flex）＋改行禁止の組み合わせにしない。ボタンは幅100%のブロック要素で置き、文字が大きくなっても折り返して収まる形にする（端末の文字拡大ではみ出す事故の再発防止）。
- フッターの導線は、文字のリンクを縦に並べただけの形にしない。グループ見出し＋説明つきのカードで組み、トップのセクションと同じ設計言語で回遊できる面にする。
- 競合の構成調査（2026-11-20、9サイト＋実ブラウザ3サイト）で確定した標準形：ヘッダーはPCでは横並びナビ（4〜5項目）＋CTAボタン、モバイルはメニューボタン。フッターはグループ見出しつきのテキストリンク列で、リンク先に索引ページ（カテゴリ別・条件別の一覧）を持つ。記事ページの標準装備は冒頭の目次とCTA、末尾の運営・監修ブロック。本文中のリンクと索引ページが回遊の主役で、フッター自体はコンパクトな地図に徹する。当サイトもこの形に合わせる（索引ページ＝記事一覧・手法一覧、カードは索引ページ側に置く）。
- 手法の分類は、手法名の羅列ではなく性質の前段分類で見せる（横断型の競合の標準形。創業手帳＝出資／借入・融資／資産の現金化／補助金・助成金の4分類が典型）：借りる（公的・銀行系）／借りる（民間の融資）／売掛金を現金化する／公的な支援／その他の調達、の5群を手法一覧の正とする。状態チェックの段階（上位→下位）もこの群と対応させる。
- 強みは文言でなく構成で見せる（2026-11-20）：トップの02に「このサイトの違い」として4つの強み（全手法の横断／結果をその場で全部出す／費用は下限と上限の両方・推測で埋めない／公式ページの観測と変更の記録）を置き、各カードから裏づけのページ（手法一覧・状態チェック・掲載基準・観測の記録ページ）へつなぐ。観測の記録は専用ページ（observation.html、全件＋仕組み）を持ち、トップには直近だけを出す。手法ページのパンくずには性質の群名を入れる。
- 記事の標準装備（2026-11-23）：全記事に図（SVGの構造図）1つ以上・表1つ以上・FAQ節（3〜5問）を入れ、構造化データは Article（著者・発行者・公開日・更新日つき）＋BreadcrumbList＋FAQPage を自動で付ける。2社間ファクタリングの手順記事には HowTo も付ける。仕様の正本は files/記事の図表とFAQ_仕様_20261123.md。数値は本文・DB・根拠資料にあるものだけを使い、DB由来の表には出典注記を付ける。
- 会社・サービスページの標準構成（2026-11-23）：全ページ同じ見出し構成・同じ情報量で統一する。会社ページ＝会社情報／事業内容／条件の要約／所在地（住所＋地図）／支店・営業所／評判と確認できること（公表状況の一覧＋実績の公表値＋Googleマップの口コミへのリンク。当サイトは口コミを掲載しない）／提供サービス。サービスページ＝条件／特徴／運営会社について／関連サービス。データが無い項目は欄を消さず「公表を確認できていません」と出す。会社の基本データ（所在地・代表者・設立・資本金・許認可）は資金調達DB（事業体DB）が正で、支店と事業内容は site/profiles.json、地図の座標は site/geocache.json（国土地理院の住所検索で取得）を使う。
